What Robinhood Chain is

The short version, before the specs.

01

Permissionless L2

A fully EVM-compatible Arbitrum Orbit chain — any developer can connect and deploy contracts without needing permission.

02

Built for RWA

Primary use case is tokenized real-world assets: equities, ETFs, and other instruments made tradable on-chain, 24/7.

03

Wallet-native

Natively supported by Robinhood Wallet; any EVM wallet or JSON-RPC client can connect through standard config.

Tokens

The ERC-8056 stock-token standard

How Stock Tokens actually work under the hood — not just "they're ERC-20."

Stock Tokens are tokenised debt securities issued by Robinhood Assets (Jersey) Limited ("RHJ"). Holding one gives economic exposure to an underlying share or ETF — it does not grant legal or beneficial ownership in the underlying security, and the tokens are not available to US persons (with further restrictions in jurisdictions including Canada, the UK, Switzerland and the UAE). Each token is a standard ERC-20 contract with 18 decimals, one per ticker.

Because corporate actions (splits, dividends) change the economics of a stock but Robinhood didn't want rebasing balances, Stock Tokens layer ERC-8056 — a "scaled UI amount" interface — on top of plain ERC-20. A multiplier is tracked on-chain; raw balances stay fixed, and UI-facing value is derived by applying the multiplier at read time.

ERC-8056 — IScaledUIAmount interface
interface IScaledUIAmount { // Current UI multiplier, 18 decimals (1e18 = 1.0) function uiMultiplier() external view returns (uint256); // Emitted when the multiplier changes (dividend, split, etc.) event UIMultiplierUpdated( uint256 oldMultiplier, uint256 newMultiplier, uint256 effectiveAtTimestamp ); // Fires on transfer, carrying raw value + UI-adjusted (share) value event TransferWithScaledUI( address indexed from, address indexed to, uint256 value, uint256 uiValue ); }

Agents and indexers building on Stock Tokens should subscribe to UIMultiplierUpdated to catch corporate-action adjustments, and read uiValue from TransferWithScaledUI rather than the raw ERC-20 Transfer event when the number needs to reflect actual underlying-share economics.

Reading price via the Chainlink feed
// Every Stock Token has a live Chainlink price feed function holdingValueUsd( IERC20 stockToken, AggregatorV3Interface priceFeed, address user ) external view returns (uint256) { uint256 balance = stockToken.balanceOf(user); (, int256 price, , uint256 updatedAt, ) = priceFeed.latestRoundData(); require(price > 0 && updatedAt > 0, "Invalid price"); // price: 8 decimals, balance: 18 decimals return (balance * uint256(price)) / 1e8; }
Standard ERC-20 calls still work
IERC20 nvda = IERC20(NVDA_TOKEN_ADDRESS); uint256 balance = nvda.balanceOf(user); nvda.transfer(recipient, amount); nvda.approve(spender, amount); // No special SDK needed for basic reads/writes — // ERC-8056 only matters when you need UI-accurate // values across corporate actions.
Canonical addresses: a token with a matching name or ticker but a different contract address is not the real Robinhood Stock Token. Always resolve addresses from the official Token Contracts page (docs.robinhood.com/chain/contracts/) before trusting a balance or a price feed.
Cache the multiplier, decode the event
// listen once, reuse until the next update let multiplier = await stockToken.uiMultiplier(); stockToken.on("UIMultiplierUpdated", (oldM, newM) => { multiplier = newM; // swap in the new scalar }); stockToken.on("TransferWithScaledUI", (from, to, value, uiValue) => { // uiValue already reflects the current multiplier — // no need to multiply raw `value` again client-side renderTransfer({ from, to, shares: uiValue }); });
